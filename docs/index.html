🔍 CommitLens

Point it at any git repo and it answers the questions every maintainer quietly worries about: who actually carries this codebase? Where is the churn? Which files have gone stale?

See a real sample report → GitHub repo

🚌 Bus factor

The fewest authors covering half your files. A bus factor of 1 is a risk you can finally put a number on.

🔥 File churn

Your hottest files by commits and changed lines — with the top author for each, so ownership is obvious.

🕐 Commit rhythm

A weekday × hour heatmap of when the team actually works. Night-owl repo? Weekend repo? Now you know.

🕸️ Stale files

Files untouched for months, surfaced before they become archaeology nobody dares to touch.

🐘 Large commits

Commits over your line threshold, ranked — the "vendor the big dataset" moments, found instantly.

📄 Self-contained reports

One HTML file, no server, no CDN, no tracking. Drop it in a PR, an audit, or a handover doc.

Run it

Python 3.10+ and git. Nothing to install — clone and run:

WhatCommand
Text reportpython3 -m commitlens /path/to/repo
HTML reportpython3 -m commitlens /path/to/repo --format html -o report.html
JSON for toolingpython3 -m commitlens /path/to/repo --format json
Last quarter onlypython3 -m commitlens /path/to/repo --since 2026-07-01
Tune the dialspython3 -m commitlens /path/to/repo --stale-days 90 --large 300 --top 20

Why it exists

Repo hosting tells you stars and forks. It never tells you that one person touches half the files, that engine.py absorbs every change, or that nobody has looked at the billing module since January. CommitLens reads the history you already have and turns it into the handover doc, the audit answer, and the "we should fix this" list — in one command.
